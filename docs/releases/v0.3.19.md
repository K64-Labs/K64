# K64 v0.3.19 - Independent User Contexts

This release moves K64's ring-3 `/ex` process model beyond reserved child identity. `spawn()` now creates a stable child process record that can be collected through `waitpid(K64_WAIT_BLOCK)`, and blocking wait enters the reserved child user context, preserves the parent syscall context, records the child exit or fault status, writes the result back through checked user memory, and reaps the child.

The ELF loader now uses a small nested execution context stack instead of one global loader VM descriptor, and the wait path gives nested children a separate syscall stack so child syscalls cannot overwrite the parent's suspended syscall frame. New smoke programs cover blocking child waits, multiple child collection, faulted-child waits, and cooperative parent/child process behavior.

K64 still is not POSIX-compatible and does not yet provide fork/execve, a dynamic linker, shared libraries, full sockets, mature VFS semantics, or timer-preemptive ring-3 process scheduling. v0.3.19 is a cooperative, wait-driven user-context step that keeps the v0.3.18 K64FS/stat/range-I/O work intact while preparing the kernel for fuller independent user scheduling.
