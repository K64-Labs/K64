# K64 v0.3.22 - Multiuser Permission Core

This release adds the first POSIX-like multiuser permission layer to K64. Accounts now have numeric runtime UIDs, groups have runtime GIDs, filesystem metadata reports owner and group IDs, and service-backed filesystem operations check owner/group/other read, write, and execute bits before opening, listing, writing, moving, or executing paths.

`sudo` now participates in the effective-user model: `sudo`, `sudo on`, and `sudo <password>` elevate the current session to effective root, while `sudo off` drops elevation again. User homes are created with owner/group metadata and private default modes, `/tmp` is writable, and `fsctl` now exposes root-only `chmod` and `chown` commands.

K64 is still not POSIX-compatible. UID/GID ownership is runtime metadata in this release and is rebuilt from the user database during boot; current legacy image filesystem images persist mode bits but do not yet store dedicated owner/group fields. The permission checks are enforced through service-backed paths and shell filesystem commands, while the lower legacy image filesystem helper layer remains a kernel mechanism for trusted callers.
