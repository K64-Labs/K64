# K64 v0.3.31 - Ring-3 Message Service Core

This release adds the first real Ring-3-message-backed service-call path. K64
can now register service methods with the `ring3-msg` backend, queue a copied
request for the owner service, enter the service's Ring-3 host image, receive
the message through `svc.recv`, and collect the bounded reply through
`svc.reply`.

The new `demo` service validates this path with `demo.echo`, `demo.upper`, and
`demo.pid`. These methods are handled by `/ex/demosvc.elf` in Ring 3 rather
than by a direct kernel function pointer. The `demosvctest.elf` smoke program
and shell smoke commands verify that the message-backed service works through
the normal `service_call` ABI.

This is still a cooperative, synchronous server foundation. Core services such
as `fs`, `proc`, `io`, `sched`, and `term` remain Ring-3-gated but
kernel-mediated while K64 still lacks persistent blocked service tasks and
preemptive user scheduling. The new message ABI is the path for moving those
services out of kernel-mediated handlers safely.
