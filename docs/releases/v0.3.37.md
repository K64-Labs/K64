# K64 v0.3.37 - KLCS Dynamic Linux App Bridge

This release makes KLCS run staged Linux x86_64 ELF programs through a real
Linux syscall gate and a first dynamic-loader bridge. K64 programs the x86_64
`syscall` MSRs, enters a KLCS Linux syscall gate from Ring 3, marks launched
KLCS programs with a Linux process personality, and routes Linux syscalls
through native K64 services and KLCS compatibility helpers.

The release includes a deterministic static Linux smoke binary,
`/compat/linux/bin/klcs-hello`, which can be launched with:

```text
klcs run klcs-hello
```

Expected output:

```text
klcs-hello: Linux syscall ABI works
```

The release also stages selected dynamically linked Linux tools and launches
them through `/compat/linux/lib64/ld-linux-x86-64.so.2`:

```text
klcs run tcc -v
klcs run git --version
klcs run nano --version
```

This is still not a complete Linux kernel ABI. KLCS now covers loader/libc
startup, TLS, anonymous memory mapping, `brk`, file descriptor reads/writes,
stat/open/readlink paths, time, randomness, and common startup stubs well enough
for basic staged tool execution. Larger `git` workflows, fully interactive
`nano`, and general Linux package execution still need more syscall and process
semantics.
