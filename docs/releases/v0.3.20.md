# K64 v0.3.20 - Service Call ABI Core

This release introduces a service-call registry parallel to the existing service command registry. Services can now expose programmatic methods such as `kernel.version`, `kernel.uptime`, `fs.stat`, `fs.list_dir`, `fs.write_file`, `proc.info`, `proc.spawn`, and `proc.wait`.

Existing syscall numbers remain compatible, but selected syscalls now route through service-backed implementations. The new `service_call` syscall copies user requests into bounded kernel staging buffers before dispatch, returns stable `K64_ERR_*` codes, and never exposes raw kernel pointers or handler addresses to userland.

v0.3.20 also adds `calls` and `call` shell tooling, libc wrappers for direct service calls, and smoke programs for successful service calls, filesystem service metadata, process service metadata, and bad-call error handling.

K64 services are still mostly kernel-side in this release. Full Ring-3 service registration and message-driven service processes remain future work, but the ABI now gives K64 a path to move more system functionality behind service-owned APIs without constantly expanding the syscall table.
