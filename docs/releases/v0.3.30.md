# K64 v0.3.30 - Service ABI Hardening

This release tightens K64's service-call-only userland ABI. Feature-specific
syscalls `1..24` are now closed directly in the syscall handler with no dormant
compatibility switch path. Syscall `25` remains the supported `service_call`
gate, and syscall `0` remains only as a minimal emergency exit path for early
service-host bootstrap.

`service_call` now validates service and method names before dispatch: names
must be non-empty, NUL-terminated inside their fixed limits, and limited to
ASCII letters, digits, `_`, `-`, and `.`. Bad pointers return
`K64_ERR_FAULT`, malformed names return `K64_ERR_INVAL`, oversized payloads
return `K64_ERR_OVERFLOW`, and unknown methods still return `K64_ERR_NOENT`.

The service-call registry now records an explicit backend type. Existing calls
remain kernel-hosted, while the registry can represent future `ring3-msg`
service calls without changing the userland ABI. The `calls` command shows the
backend for each registered method.

The new `servicefuzz.elf` smoke program exercises malformed service-call
inputs, bad pointers, oversized payloads, permission failures, and recovery to
a valid `kernel.version` call.
