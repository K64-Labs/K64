# K64 v0.3.32 - Cooperative Async User Processes

This release removes the strict wait-only child execution path. `proc.spawn` still returns a stable child PID immediately, but queued children can now run from cooperative scheduler points such as `sched.yield`, `sched.sleep`, and the shell/service poll loop before the parent calls `proc.wait`.

The release also adds a `backgroundspawn.elf` smoke program that proves a parent can spawn a child, sleep, observe work completed by that child, and then reap it. This is a step toward real parallel usermode without regressing the service-call-only ABI, K64XFS root flow, or existing process/fd/pipe tests.

K64 is still not fully timer-preemptive for Ring-3 tasks. The current model is cooperative-asynchronous, not a complete SMP or POSIX process scheduler. The next scheduler step is to replace the remaining global user context with saved per-process trap frames so timer IRQs can safely preempt CPU-bound user processes.
