# K64 v0.3.34 - Service Gate and Credential Hardening

This release tightens the service-call-only userland path and removes several sharp edges from the current microkernel-style architecture.

Highlights:

- `service_call` no longer uses one global request/response buffer depth counter. Calls now acquire bounded scratch slots, so nested service-host paths and future concurrent user contexts have a safer staging model.
- User process records now carry real/effective UID and GID fields and spawned children inherit credentials from their parent process.
- Service dispatch and filesystem service permission checks now use the active process credentials when a user process exists, falling back to the login session only for kernel/internal contexts.
- `proc.spawn`, `io.open`, `fs.stat`, `fs.list_dir`, `fs.write_file`, and service-message caller metadata now use the active process identity path.
- Generated local artifacts, KDesk scratch files, test binaries, and disk images are ignored to reduce accidental release pollution.
- Syscall ABI docs now describe the current cooperative child progress behavior instead of the older strictly wait-driven text.

K64 is still not fully timer-preemptive for Ring-3 user processes. v0.3.34 is a correctness and security hardening release that prepares the service-call and credential paths for the larger scheduler and true Ring-3 service-server work.
