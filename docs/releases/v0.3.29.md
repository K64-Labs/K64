# K64 v0.3.29 - Kernel-Only Ring 0 Service Identity

This release tightens the v0.3.28 Ring-3 service gate so the only service identity allowed to remain Ring 0 is the literal `kernel` service. Core service owners such as `fs`, `proc`, `io`, `sched`, `term`, and `svc` are now registered as system service facades and must pass the Ring-3 startup probe before their commands or service calls can dispatch.

`servicectl list` should now show `ring0` only for `kernel`; everything else is either `ring3` after verification or `blocked` if the Ring-3 entry image cannot be entered. K64 also switches `/ex/servicehost.elf` to a tiny assembly probe so the gate does not depend on `proc.exit` while `proc` itself is being verified.

This is still an incremental migration. Low-level filesystem, process, terminal, scheduler, network, and hardware mechanisms are still implemented inside the kernel boundary, but they no longer present themselves as Ring-0 service identities. The remaining work is a persistent message-driven Ring-3 service server so service-specific logic can move out from the kernel-mediated compatibility path.
