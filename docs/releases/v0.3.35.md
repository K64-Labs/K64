# K64 v0.3.35 - K64XFS Recovery and Pseudo-FS Hardening

This release hardens several pieces that were still too rough after the service-call and credential work.

Highlights:

- K64XFS metadata journaling now writes bounded metadata-block records, commit records, and replayable transactions instead of behaving as a no-op skeleton.
- Dirty or recovery-needed K64XFS mounts scan the journal, replay committed metadata records, discard incomplete transactions, clear the journal, and mark the volume clean after recovery.
- The K64XFS checker now catches more malformed filesystem states, including bad root inode state, invalid inode types, extent-count overflow, zero-length or out-of-range extents, bitmap mismatches, and overlapping extents on supported volumes.
- The root filesystem image builder now uses the same 32-block K64XFS journal geometry as the kernel formatter.
- The filesystem facade exposes initial pseudo-filesystem paths: `/proc/version`, `/proc/services`, `/dev/null`, `/dev/console`, and `/dev/tty0`.
- Shell smoke now verifies `/proc` and `/dev` paths.
- GitHub Actions opts into Node 24 for JavaScript actions to remove the upcoming Node 20 runner warning.
- Local generated graphics/mouse scratch files are ignored so they do not pollute release commits.

K64 still does not yet have full timer-preemptive Ring-3 user scheduling. That remains a dedicated trap-frame and scheduler architecture change rather than a small hardening patch.
