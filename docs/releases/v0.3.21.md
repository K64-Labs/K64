# K64 v0.3.21 - Service-Only User ABI

This release makes `service_call` the only supported Ring-3 syscall gate. The old feature-specific syscall numbers now return `K64_ERR_NOSYS`, while the libc wrappers for process, scheduler, fd, pipe, filesystem, terminal, and text-framebuffer operations marshal named service calls instead.

K64 now exposes service methods for `io.*`, `fs.*`, `proc.*`, `sched.*`, `term.*`, and `kernel.*`, and the original `hello` and `catmotd` smoke programs use the same C/libc service-call path as the rest of userland.

Services are not yet fully hosted as untrusted Ring-3 service processes. v0.3.21 tightens the ABI boundary and prepares that migration, but message-driven Ring-3 service registration remains future work.
